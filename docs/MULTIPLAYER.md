# Minecraft 专用联机

FYL 的「联机」通过公共 STUN 和手动交换邀请、回应信息建立两人 P2P 连接，无需开发者或玩家租用服务器，也不需要 Cloudflare 账号。当前不使用游戏中继，无法穿透的网络会连接失败。

这是应用层的 Minecraft 局域网联机：不创建系统虚拟网卡，不修改路由、DNS、系统代理或防火墙，不要求管理员权限。仅将房主本机选定的 Minecraft TCP 游戏端口连接到加入者的本机临时入口，其他应用的流量保持原样。

## 使用

1. 房主在「联机 → 创建房间」生成邀请信息，完整复制给朋友
2. 朋友选择「加入房间」，粘贴邀请并生成回应信息，再把回应完整发回房主
3. 房主导入回应，双方等待「已建立直连」
4. 房主进入 Minecraft 世界，选择「对局域网开放」；FYL 自动检测本机发布的世界，也可手动指定游戏端口
5. 朋友在 Minecraft 多人游戏列表中选择 FYL 发布的局域网世界；自动发现不可用时，复制 FYL 显示的本机游戏地址并使用「直接连接」

邀请在创建后 10 分钟内可用于建立连接，已经建立的连接不会因邀请过期而断开。邀请包含当前网络候选地址和临时授权信息，各机器网卡数量不同，实际长度可能从数百到数千字符不等，允许粘贴带换行的信息。

同一台电脑有多个局域网世界时，自动模式选取先识别到的世界；需要指定其他世界时，填写该游戏在聊天栏显示的局域网端口。手动指定仍会检查 Minecraft 状态响应，未开启状态查询的专用服务端暂不支持。

手动选择的端口会定期复验。世界关闭后停止发布地址和局域网公告；同一端口上的 Minecraft 世界恢复后，可重新发布，不会切换到另一局域网世界。

双方仍须满足 Minecraft 自身的版本、Mod 和账户验证要求。首版只承载 Java 版的游戏 TCP 连接，语音 Mod 等额外 UDP 服务暂未接入。退出启动器或点击「断开联机」会结束连接，游戏进程本身可以继续运行。

## 实现

- `native/multiplayer` 是独立、无特权的 Go 网络助手，界面通过带随机凭证的本机 TCP 控制连接管理会话
- ICE 收集 IPv4、IPv6 和 STUN 候选地址；公共 STUN 为 `stun:stun.cloudflare.com:3478`，不传输游戏内容
- 双方手动交换 `FYL1:` 信息，房主使用一次性密钥验证回应的 HMAC；信息不写入设置、账户存储、临时文件或日志
- 每次创建独立 ECDSA 证书，DTLS 使用邀请和回应中的证书指纹双向验证身份，加密密钥不跨会话复用
- SCTP 在 DTLS 上提供可靠、有序、带背压的独立游戏流，支持并行状态查询和游戏连接
- 对端不能指定目标 IP 或端口，目标始终是房主本机当前选择且已验证 Minecraft 状态的游戏服务
- 加入者的临时 TCP 入口为了局域网发现兼容性监听本机地址，但拒绝所有非本机来源，不作为物理局域网中的公共代理
- 局域网公告通过 `224.0.2.60:4445` 监听和发布；不依赖把物理局域网广播整体转发给对方

房主导入回应后，直连尝试最多等待 45 秒。朋友生成回应后可以等待至邀请过期，以便房主完成手动导入。网络丢失会尝试恢复并在超时后结束会话；保活和大流量传输在网络助手中运行，不占用 Flutter 的界面线程。

## 构建与校验

需要 Go 1.24+、Python 3 和项目原有的 Flutter、Java、各平台构建工具。Windows/Linux 的 CMake 和 macOS 的 Xcode 构建阶段自动构建网络助手，并附带依赖许可证。

网络助手位置：

- Windows/Linux：程序旁的 `data/fyl-network/`
- macOS：应用内的 `Contents/Resources/fyl-network/`

已有 Flutter Release 产物时，也可以单独补建对应助手：

```sh
python tool/build_network.py --target windows
python tool/build_network.py --target linux
python tool/build_network.py --target macos --arch universal
```

源码检查与回归测试由 CI 执行，包括邀请校验、证书身份拒绝、大流量传输与半关闭、Flutter 控制连接生命周期。真实 NAT 穿透效果还需两台不同网络的设备验证。
