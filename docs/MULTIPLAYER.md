FYL 的「联机」通过公共 STUN 和手动交换邀请、回应信息建立多人 P2P 房间，无需开发者或玩家租用服务器，也不需要 Cloudflare 账号。所有朋友分别直连房主，无需彼此互连。当前不使用游戏中继，无法穿透的朋友会连接失败，其他连接不受影响。

这是应用层的 Minecraft 局域网联机：不创建系统虚拟网卡，不修改路由、DNS、系统代理或防火墙，不要求管理员权限。仅将房主本机选定的 Minecraft TCP 游戏端口连接到加入者的本机临时入口，其他应用的流量保持原样。

## 使用

1. 房主在「联机 → 我是房主」点击「创建邀请」，将同一份房间邀请完整复制给多位朋友
2. 每位朋友选择「加入朋友」，点击「粘贴邀请并继续」生成各自的回应，再点击「复制回应」完整发回房主
3. 房主逐个点击「粘贴回应并连接」，连接列表会分别显示每位朋友的状态；也可以直接在输入框中粘贴邀请或回应。已有朋友在线时仍可继续导入其他回应
4. 房主进入 Minecraft 世界，选择「对局域网开放」；FYL 自动检测本机发布的世界，也可手动指定游戏端口
5. 朋友在 Minecraft 多人游戏列表中选择 FYL 发布的局域网世界；自动发现不可用时，展开「没有看到局域网世界？」，复制本机直连地址并在游戏中使用「直接连接」。这个地址仅供加入者本机使用，无需发送给房主

邀请默认在创建后 10 分钟内可用于建立连接，可在联机设置中调整为 1–10 分钟，已经建立的连接不会因邀请过期而断开。邀请包含当前网络候选地址和临时授权信息，各机器网卡数量不同，实际长度可能从数百到数千字符不等，允许粘贴带换行的信息。

房主可以「停止接纳新人」，或者「重新生成邀请」使旧邀请和未导入的旧回应失效，这些操作都不会断开已有连接。切换网卡或网络地址后，应结束房间并重新创建，以收集新的网络入口。每位朋友可单独断开或移除；失败后可用仍有效的房间邀请重新生成回应，无需房主单独创建邀请。连接列表中的数量代表启动器通道数，游戏内实际在线人数以 Minecraft 为准。默认每个房间最多同时建立 16 条朋友连接，可在联机设置中降低上限，游戏人数仍受 Minecraft 服务端配置和房主设备能力限制。

同一台电脑有多个局域网世界时，自动模式选取先识别到的世界；需要指定其他世界时，填写该游戏在聊天栏显示的局域网端口。手动指定仍会检查 Minecraft 状态响应，未开启状态查询的专用服务端暂不支持。

手动选择的端口会定期复验。世界关闭后停止发布地址和局域网公告；同一端口上的 Minecraft 世界恢复后，可重新发布，不会切换到另一局域网世界。

所有玩家仍须满足 Minecraft 自身的版本、Mod 和账户验证要求。目前只承载 Java 版的游戏 TCP 连接，语音 Mod 等额外 UDP 服务暂未接入。朋友退出启动器或点击「断开联机」仅结束自己的连接；房主退出启动器或点击「结束房间」会结束全部连接，游戏进程本身可以继续运行。

## 联机设置与连接诊断

联机页面内提供「房间」「联机设置」「连接诊断」三个入口，主设置页不包含联机选项。

- 可选择 IPv4/IPv6 协议与网卡、填写最多 8 个 UDP STUN 服务器、指定本地 UDP 端口（0 为自动分配），并调整 STUN 超时、房主直连超时、邀请有效期与朋友连接上限
- STUN 服务器每行一个 `stun:主机:端口`，也支持带方括号的 IPv6 地址。留空时仅使用直接可达的候选地址。多个服务器按顺序尝试，单轮回退最多等待 12 秒；STUN 不转发游戏流量，当前不提供 TURN 或 TCP 隧道
- 可以关闭房主的局域网世界自动检测，改为手动指定游戏端口；也可以关闭加入者的局域网公告，改用本机直连地址进入游戏
- 所有选项支持单项重置，保存到当前数据目录下独立的 `multiplayer.json`，随数据目录一同迁移。保存只影响下次创建房间或加入，正在运行的会话继续使用其启动时的设置
- 诊断显示本地候选、STUN 映射结果、每条连接选中的本地/远端候选、ICE 探测往返延迟、证书 SHA-256 指纹及身份验证结果，并保留最近 100 条状态与错误码事件。ICE 延迟不等于 Minecraft 游戏内延迟；当前不自动检测 NAT 类型
- 退出联机后保留上次诊断供查看或复制，也可手动清除。诊断仅保存在内存，复制内容包含 IP 地址和证书指纹，不包含邀请文本、授权密钥、ICE 密码、DTLS 私钥或账户信息

## 实现

- `native/multiplayer` 是独立、无特权的 Go 网络助手，界面通过带随机凭证的本机 TCP 控制连接管理会话
- ICE 收集 IPv4、IPv6 和 STUN 候选地址；公共 STUN 为 `stun:stun.cloudflare.com:3478`，不传输游戏内容
- 多人房间使用 `FYL2:` 邀请和回应，房主用本次邀请的随机密钥验证各回应的 HMAC；信息不写入设置、账户存储、临时文件或日志。加入者仍能使用旧版 `FYL1:` 双人邀请，多人房间需要所有玩家使用支持 `FYL2:` 的构建
- 房间保持一组共享 UDP socket 和 STUN 映射，每位朋友生成独立随机连接标识，由邀请密钥和该标识派生各自的房主 ICE 凭证，通过 UDP mux 分配至独立 ICE、DTLS 和 SCTP 会话。完整回应（包括连接标识、地址、证书指纹）均受 HMAC 绑定，重复回应不会建立第二条连接
- 每个房间生成房主 ECDSA 证书，各朋友生成自己的证书。DTLS 使用邀请和回应中的指纹双向验证身份，每条连接独立握手并使用独立流量密钥
- SCTP 在 DTLS 上提供可靠、有序、带背压的独立游戏流，支持并行状态查询和游戏连接
- 对端不能指定目标 IP 或端口，目标始终是房主本机当前选择且已验证 Minecraft 状态的游戏服务
- 加入者的临时 TCP 入口为了局域网发现兼容性监听本机地址，但拒绝所有非本机来源，不作为物理局域网中的公共代理
- 局域网公告通过 `224.0.2.60:4445` 监听和发布；不依赖把物理局域网广播整体转发给对方
- 房主只执行一次世界检测，将同一选定世界同步给全部通道，新加入者自动收到当前世界；世界关闭时向所有朋友撤回游戏入口。房间与通道分开取消，单人失败不会关闭房间或其他通道

房主导入回应后，直连尝试默认最多等待 45 秒，可在联机设置中调整为 10–120 秒。朋友生成回应后可以等待至邀请过期，以便房主完成手动导入。网络丢失会尝试恢复并在超时后结束会话；保活和大流量传输在网络助手中运行，不占用 Flutter 的界面线程。

## 构建与校验

普通构建只需 Python 3 和项目原有的 Flutter、Java、各平台构建工具，不需要 Go。编译实验性联机时另需 Go 1.24+，并显式开启同一个编译参数：

```sh
flutter run -d windows --dart-define=FYL_ENABLE_MULTIPLAYER=true
flutter build windows --release --dart-define=FYL_ENABLE_MULTIPLAYER=true
flutter build linux --release --dart-define=FYL_ENABLE_MULTIPLAYER=true
flutter build macos --release --dart-define=FYL_ENABLE_MULTIPLAYER=true
```

启用时，Windows/Linux 的 CMake 和 macOS 的 Xcode 安装阶段构建网络助手并附带依赖许可证；关闭时清理上次构建残留的助手，避免混入普通包。构建目录会记录 `fyl-build-flags.json` 供打包工具核对。此参数是编译开关，不是启动参数，修改后需要重新构建。

手动运行 Desktop 工作流时可勾选 `enable_multiplayer`，普通提交、PR 和标签发布始终保持关闭。实验产物的名称带 `-multiplayer`，不会自动发布到 GitHub Release。

联机测试也须显式开启，例如 `flutter test --dart-define=FYL_ENABLE_MULTIPLAYER=true test/multiplayer_page_test.dart`。手动打包实验版本还需给 `tool/release.py package` 添加 `--enable-multiplayer`，构建与打包开关必须一致。

网络助手位置：

- Windows/Linux：程序旁的 `data/fyl-network/`
- macOS：应用内的 `Contents/Resources/fyl-network/`

已有 Flutter Release 产物时，也可以单独补建对应助手：

```sh
python tool/build_network.py --target windows --enable-multiplayer
python tool/build_network.py --target linux --enable-multiplayer
python tool/build_network.py --target macos --arch universal --enable-multiplayer
```

源码检查与回归测试由 CI 执行，包括邀请校验、证书身份拒绝、大流量传输与半关闭、同一邀请并发连接多人、单人退出隔离、中途加入、邀请停用与换新、世界关闭同步撤回，以及 Flutter 控制连接生命周期和多语言界面。自动化多人测试使用内存网络与本机模拟游戏服务；真实 NAT 穿透效果仍需多台不同网络的设备验证。
