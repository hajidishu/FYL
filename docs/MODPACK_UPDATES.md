# 整合包升级

入口：版本设置 → 概览 → 检查整合包更新。支持 Modrinth、CurseForge 的同项目版本选择，以及从本地 `.mrpack`、CurseForge ZIP 更新。CurseForge 需要配置 API Key；受下载限制的文件沿用下载任务的手动补全流程。

新版先安装到独立暂存版本，再比较来源记录中的作者文件哈希与当前文件。未改动文件跟随作者更新或移除；用户新增文件保留；双方都修改的文件逐项选择，默认保留本地版本。存档、截图、服务器列表和个人游戏选项默认保留。旧安装没有哈希时，无法判断的文件按冲突处理。

已有安装缺少哈希时，会尝试从原安装保留的下载缓存、覆盖文件缓存重建作者基线。缓存也缺失的文件仍保守地列为冲突，并默认推荐更新到副本。

跨 Minecraft 版本、更换加载器时默认创建副本；未隔离的整合包只能升级到隔离副本。应用升级前会重新检查原版本，拒绝在游戏运行或文件已经变化时继续。下载、哈希和数据合并使用现有后台流程或独立 isolate。

原地升级保留完整旧版本到游戏根目录 `.fyl/pack-backups/<任务 ID>/version`，并保存旧版本设置，可在概览中还原。还原会恢复备份时的存档与配置；还原前的当前目录会另存为 `.reverted`，不会直接删除。升级副本和完整备份都需要额外磁盘空间。

暂存取消的版本移入 `.fyl-trash/unused-update-*`。目录发布与启动器配置之间的恢复记录位于数据目录 `pack-update-journal.json`，在启动器初始化时检查。来源记录保存在各版本 `.fyl/modpack.json`，其中 `fileHashes` 始终记录作者安装基线，不会用用户保留的配置覆盖基线。
